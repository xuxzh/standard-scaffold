# UI 文档

这个目录用于沉淀当前脚手架的长期 UI 约束，回答的是“界面默认应该怎样组织、实现和验收”，而不是“某个页面这次具体长什么样”。

## 适合放什么

- 应用壳层和布局约束
- 组件使用优先级与复用边界
- 常见交互状态规范，如 loading、empty、error、disabled
- 可访问性和响应式的最低要求
- 设计 token、排版、表单、表格等通用 UI 模式

## 不适合放什么

- 单个页面的视觉稿或一次性方案讨论
- 某次任务的实施步骤
- 仅在某个局部页面生效、尚未形成通用模式的规则

这类内容应继续放在 `docs/specs/`、`docs/plans/`，或留在页面所属 feature 设计中。

## 与组件代码的边界

当前仓库约定：

- 应用本地 UI 基础组件在 `apps/web/src/components/ui`
- 应用壳层在 `apps/web/src/components/layout`
- `packages/ui` 仅作为按需共享的基础设施，不是应用内组件的默认落点

因此，这个目录用于说明默认取舍和使用边界，而不是替代组件源码本身。

## 首批文档

- `application-ui-guidelines.md`：当前 Web 脚手架的应用 UI 实现规范
- `form-patterns.md`：Web 表单的默认技术选型、字段结构、错误态和示例入口

## 维护规则

- 当某种页面模式、壳层约束或组件取舍会被多个功能复用时，沉淀到这里。
- 当规范背后的长期方向变化时，用 `docs/adr/` 记录原因，再回写这里。
- 能被组件库、测试或 lint 完整约束的内容，文档只保留默认做法和例外，不重复罗列细枝末节。
