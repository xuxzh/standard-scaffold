# 登录页开发环境默认账号密码设计

## 背景

当前登录页在所有环境下都以空白表单初始化。为了提升本地演示和开发联调效率，希望在开发环境打开登录页时，自动填入一组可直接提交的演示账号密码。

## 目标

- 仅在开发环境为登录表单默认填入 `DemoAdmin` 和 `Icpt1357!!`。
- 保持现有登录提交、跳转和校验行为不变。

## 非目标

- 不在生产环境或其他非开发环境默认展示账号密码。
- 不新增新的登录接口、认证逻辑或存储逻辑。
- 不引入额外的“演示账号填充”按钮。
- 不新增环境变量配置。

## 范围级别

- 建议任务级别：`L0`
- 原因：改动集中在登录页表单默认值和一条对应测试，范围小、边界清晰、无跨模块数据流调整。

## 受影响边界

- `apps/web/src/features/auth/login-page.tsx`
  - 调整表单初始化默认值。
- `apps/web/src/features/auth/login-page.test.tsx`
  - 增加开发环境默认填充断言，确保行为可验证。

## 建议方案

在 `LoginPage` 内基于 `import.meta.env.DEV` 生成表单默认值：

- 开发环境：`userCode = "DemoAdmin"`，`password = "Icpt1357!!"`
- 非开发环境：两个字段都保持空字符串

这样可以直接复用现有 `useForm({ defaultValues })` 结构，不需要新增状态层或配置读取逻辑，也不会影响登录成功后的 token 持久化和跳转逻辑。

## 备选方案

### 方案 A：通过 `VITE_LOGIN_DEMO_*` 环境变量注入

- 优点：账号密码可配置，不必硬编码。
- 缺点：超出本次最小需求，需要补充额外环境约定和文档。

### 方案 B：增加“填充演示账号”按钮

- 优点：避免页面一打开就显示密码。
- 缺点：不符合“默认填入”的直接诉求，并会额外引入一段交互逻辑。

本次不采用备选方案，优先选择 `import.meta.env.DEV` 的最小实现。

## 数据流

1. 组件初始化时判断当前是否为开发环境。
2. 将对应默认值传给 `useForm({ defaultValues })`。
3. 用户可直接提交默认账号，后续登录流程保持不变。

## 验证计划

- `pnpm --filter @repo/web test -- login-page`
- `pnpm --filter @repo/web typecheck`
- 对最近编辑文件执行诊断检查，确认没有新增 lint 或类型问题。

重点验证：

- 开发环境渲染登录页时，账号和密码输入框已带默认值。
- 现有登录提交流程测试仍然通过。
- 空表单校验逻辑在非开发环境分支下未被意外破坏。

## 风险

- 测试环境默认是否视为开发环境，需要通过显式 stub 环境变量避免测试结果依赖执行器默认配置。
- 如果默认值直接散落在组件内部，后续改动时可能出现重复字面量，建议保持常量集中。
