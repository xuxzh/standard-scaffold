# API 文档

这个目录用于沉淀仓库内长期有效的接口契约和远程集成约束，回答的是“前端默认应该如何对接接口”，而不是“某次需求接口怎么设计”。

## 适合放什么

- 通用 HTTP 契约约定
- 请求参数与响应字段的命名规则
- 分页、筛选、排序、时间字段等通用接口语义
- 错误结构、错误码映射、鉴权和环境约束
- 与 OpenAPI 或人工维护接口清单相关的入口文档

## 不适合放什么

- 某一次需求的设计讨论
- 单次任务的执行步骤
- 仅存在于某个 feature 内、还没有被证明可复用的临时约定

这类内容应分别进入 `docs/specs/`、`docs/plans/`，或先留在功能设计文档中，等稳定后再抽取到这里。

## 与代码的对应关系

当前 Web 应用默认沿用 `contract -> service -> route/component` 的数据访问路径：

- `contract` 负责定义前端消费接口时的输入输出结构
- `service` 负责封装调用和错误归一化
- `route/component` 负责消费已归一化的数据和状态

因此，这个目录描述的是这些层之间共同依赖的契约约束，而不是替代具体代码实现。

## 首批文档

## 维护规则

- 当某个接口约定影响多个 feature，或未来很可能被反复复用时，补到这里。
- 当约定背后的长期方向发生变化时，用 `docs/adr/` 记录原因，再回写这里的默认做法。
- 能被代码生成、类型系统或测试完全表达的规则，不重复展开成大段文档，只保留入口说明和例外。
