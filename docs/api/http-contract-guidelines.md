# HTTP 接口契约规范

本文档定义当前脚手架在 Web 应用中对接 HTTP 接口时的默认约束。它是通用基线，不替代某个具体业务接口的字段说明。

## 适用范围

- `apps/web/src/features/*` 中的 feature contract 和 service
- `apps/web/src/lib/api/*` 中的通用请求与错误处理逻辑
- route、loader、组件对远程数据的消费方式

## 基本原则

### 前端先消费稳定契约，不直接把接口细节扩散到页面

页面或 route 不应直接拼接请求结构、解析原始错误对象或散落处理字段兼容逻辑。默认做法是：

1. 在 feature 下定义或收敛消费侧 contract
2. 在 service 中完成请求、解析和错误归一化
3. 在 route 或组件中只消费已整理的数据和状态

### 优先保持字段语义清晰，而不是机械映射后端命名

如果后端字段命名不适合直接暴露给页面，可以在 `service` 或 `contract` 层做一次稳定映射。页面层应优先面对稳定、易懂、与 UI 语义一致的数据结构。

## 请求与响应命名

- TypeScript 类型、接口、schema 名称使用英文语义化命名。
- 单个资源优先使用 `xxxId`、`createdAt`、`updatedAt` 这类稳定命名。
- 布尔字段优先使用 `is`、`has`、`can` 前缀。
- 避免在页面层直接传播 `data`, `list`, `item` 这类信息量过低的泛名；在 contract 中用领域名说明含义。

如果后端字段风格与前端默认风格不同，前端内部可做适配，但同一 feature 内要保持统一，不要一部分用 `snake_case` 一部分用 `camelCase`。

## 分页、筛选与排序

### 分页

- 默认显式区分分页参数和分页结果。
- 请求参数至少要能表达当前页、页大小，或游标分页所需游标字段。
- 响应结构应能清晰表达列表项和分页元数据，不要把总数、是否有下一页等信息散落到多个不稳定字段上。

如果后端接口风格不统一，前端应在 service 层归一化为一个稳定分页模型，再向页面暴露。

### 筛选

- 筛选参数应按业务含义命名，不要把 UI 临时状态对象原样透传为请求参数。
- 空字符串、`undefined`、`null` 的语义需要在 feature 内统一；默认不要把无意义空值发给接口。

### 排序

- 排序字段和值应使用稳定枚举或受限字符串，而不是由页面直接随意拼接。
- 若接口支持多字段排序，在 contract 中明确顺序语义和默认值。

## 错误结构约定

### 统一在 service 或 `lib/api` 层归一化错误

页面和 UI 组件不应直接依赖底层 `fetch`、HTTP client 或服务端原始异常结构。默认应在 service 或 `apps/web/src/lib/api` 中归一化为前端可消费的错误模型。

建议至少区分以下类别：

- 网络不可达或超时
- 鉴权失败或权限不足
- 资源不存在
- 服务端异常
- 可直接展示给用户的业务错误

### 面向 UI 暴露的错误对象应稳定

面向 route 或组件暴露的错误对象，至少应保证：

- 有稳定的分类字段
- 有可用于日志与排障的原始信息入口
- 有可选的用户可见文案或文案 key

不要让页面自己猜测状态码再决定提示文案。

## 日期时间与时区

- 接口文档中应明确时间字段是 UTC 时间戳、ISO 字符串还是本地时间。
- 前端内部默认优先使用可明确时区语义的格式，不要混用“看起来像本地时间”的字符串。
- 展示格式转换应靠近 UI 层，原始时间语义归一化应靠近 service 或 contract 层。

## 鉴权与环境边界

- 鉴权头、租户头、环境差异等通用约束应集中在 `apps/web/src/lib/api` 一层处理。
- 页面和 feature service 不应重复拼接相同的环境或鉴权逻辑，除非该接口确实属于特例。
- 一旦出现特例，应在对应 feature 文档或 spec 中说明原因，不要默默偏离基线。

## 与测试的关系

- contract 的变化优先补单元测试或数据层测试，确保解析和映射稳定。
- 用户可见的数据状态变化需要在 route 测试或页面测试中体现。
- 影响主链路接口行为时，应评估是否需要补 E2E。

## 何时更新本文档

当以下情况出现时，应回写这里：

- 多个 feature 开始重复使用同一种分页、错误或时间处理模式
- `apps/web/src/lib/api` 的默认约定发生变化
- 某类接口集成错误被证明是高频坑，值得沉淀为统一规则
